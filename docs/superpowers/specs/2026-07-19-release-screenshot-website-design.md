# 正式版截图官网重构设计

## 目标

以五张当前 Android 界面截图替换已删除的旧角色素材和手绘模拟界面；官网明确发布 Android 正式版 APK，并让带推荐码访问的下载路径继续与 App 的既有邀请归因机制衔接。

## 页面结构

1. **首屏**：使用“语音通话”截图作为产品主视觉。保留产品定位、下载 CTA、配置指南以及带 `?ref=` 时的推荐码横幅。
2. **能力区**：保留四项能力说明，作为截图画廊的功能导览。
3. **产品展示区**：采用响应式截图画廊，按“文本聊天、语音通话、发现智能体、列表对话、会员与邀请”的顺序展示。大屏突出语音通话和文本聊天；小屏改为单列或两列卡片。每张图片有中文标题和简短说明。
4. **下载区**：将所有“测试版／公开测试”措辞改为“Android 正式版”。下载目标保持 `public/downloads/linglong-mas.apk`，二维码继续指向该文件。

## 推荐码与邀请归因

- URL 的 `ref` 参数仍在 React 层读取，空白值视为无推荐码。
- 带推荐码时，首屏展示该代码，并在用户点击下载前提供显式“复制推荐码”操作；页面加载时可继续尽力写入剪贴板。
- 写入格式保持 `LL_REF:<推荐码>`，与 Android 首启读取和已有邀请关系绑定逻辑兼容。
- 官网不创建会员、账户或邀请关系，也不保存推荐码；它只传递邀请码，归因由 App 侧现有实现完成。

## 实现边界

- 仅重构 `src/main.jsx` 与 `src/styles.css`，使用已在 `public/assets` 中替换好的五张 PNG。
- 删除旧素材数组、旧精灵卡片和手绘手机组件的引用；不恢复已删除的旧图片。
- 将邀请码 toast 的直接 DOM 操作迁回 React 组件，避免与 React 生命周期并行修改页面。

## 验证

- `npm run build` 成功，且构建产物不引用已删除的旧图片路径。
- 带与不带 `?ref=` 分别检查：推荐码横幅/复制操作只在带码时出现。
- 在桌面与窄屏宽度下检查截图画廊无裁切、文本可读、下载 CTA 与二维码均指向正式版 APK。
